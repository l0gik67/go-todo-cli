# Go Todo CLI

Небольшой учебный консольный список дел на Go. Приложение позволяет управлять задачами и хранит журнал всех команд, введённых пользователем во время текущего запуска.

Проект создан для закрепления базовых возможностей языка после первой части [полного курса по Golang](https://www.youtube.com/watch?v=dpvRDJjUJf8). Это не production-ready приложение: его главная цель — практика, а не демонстрация промышленной архитектуры.

## Что реализовано

- добавление задачи с уникальным заголовком из одного слова и произвольным текстом;
- сохранение времени создания задачи;
- вывод полного списка задач;
- отметка задачи как выполненной с сохранением времени выполнения;
- удаление задачи по заголовку;
- проверка формата команд и понятные сообщения об ошибках;
- журналирование каждой введённой строки, включая ошибочные команды;
- сохранение текста ошибки и времени создания события;
- вывод задач в стабильном порядке по заголовку;
- форматированный вывод с помощью сторонней библиотеки [`github.com/k0kubun/pp`](https://github.com/k0kubun/pp).

Задачи и события хранятся только в оперативной памяти. После завершения программы данные сбрасываются — сохранение в файл или базу данных в текущую учебную версию не входит.

## Команды

| Команда | Назначение |
| --- | --- |
| `help` | Показать список доступных команд и их формат |
| `add {заголовок} {текст}` | Добавить новую задачу |
| `list` | Показать все задачи |
| `del {заголовок}` | Удалить задачу |
| `done {заголовок}` | Отметить задачу как выполненную |
| `events` | Показать журнал пользовательских событий |
| `exit` | Завершить программу |

Заголовок должен состоять ровно из одного слова. Текст задачи должен содержать хотя бы одно слово и может быть произвольной длины.

## Пример использования

```text
help
add course Посмотреть следующий урок по Go
add practice Решить несколько задач
list
done course
events
del practice
exit
```

Команда `events` также попадает в журнал и отображается в выведенном списке. Для успешных команд описание события остаётся пустым, а для неуспешных содержит текст ошибки.

## Запуск

Понадобится версия Go, указанная в [`go.mod`](go.mod).

```bash
git clone https://github.com/l0gik67/go-todo-cli.git
cd go-todo-cli
go mod download
go run .
```

Сборка отдельного исполняемого файла:

```bash
go build -o go-todo-cli .
```

На Windows можно указать имя `go-todo-cli.exe`.

## Тесты и проверка кода

Запуск всех тестов:

```bash
go test ./...
```

Статический анализ:

```bash
go vet ./...
```

## Структура проекта

```text
.
├── entity/
│   ├── event.go   # событие и журнал событий
│   ├── event_test.go
│   ├── task.go    # задача и хранилище задач
│   └── task_test.go
├── main.go        # чтение ввода, команды и форматирование вывода
├── main_test.go   # тесты команд и сквозного сценария
├── .gitignore     # исключения для Git
├── go.mod         # Go-модуль и список зависимостей
├── go.sum         # контрольные суммы зависимостей
└── README.md
```

Основной пакет отвечает за взаимодействие с пользователем, а пакет `entity` содержит модели задач и событий и операции над ними.

## Что практикуется в проекте

- структуры, методы и указатели;
- `map` и срезы;
- пакеты и Go-модули;
- обработка ошибок;
- работа со строками, потоками ввода-вывода и временем;
- подключение сторонней зависимости;
- тестирование и статический анализ.

## Идеи для развития

- сортировать задачи по разным полям;
- добавить сроки выполнения и приоритеты;
- сделать HTTP API или веб-интерфейс;
- добавить интеграцию с `golangci-lint` и GitHub Actions.
